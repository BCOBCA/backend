# Product variant options

- Root cause: all 21 demo products had one `Phiên bản mẫu` variant with `{}` attributes; the public detail DTO omitted attributes, and the frontend displayed a flat list below the long description.
- `VariantDto` now adds optional `Attributes` (scalar string values) and `IsSample`. `CatalogVariantMapper` parses stored JSON safely, retaining purchasable variants when legacy JSON is malformed. No migration is required.
- Frontend groups options by color/storage/size and other scalar attributes, resolves selections to real in-stock combinations, preserves other options where possible and disables sold-out choices. Product ID scopes selection; displayed price/stock and cart ID follow the selected variant. Controls appear directly below the price. ARIA checked/disabled props are explicit for React Native Web; native accessibility state is also set.
- The deployed API currently lacks structured attributes. Explicitly labeled sample variant names (`[Mẫu] Màu sắc: … · Dung lượng: …`) support the new frontend immediately. Deploy the backend code to expose structured fields for all future variants. Unstructured legacy variants keep a flat selector.
- User authorized sample variants, unchanged prices and redistribution of existing stock. Original variant IDs/SKUs remain; no variant rows were deleted. Existing product details, five-image galleries, prices and dealer links remain intact.
