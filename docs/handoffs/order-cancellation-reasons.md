# Confirmation and cancellation notifications

- Buyer and seller cancellation is restricted to PENDING + UNPAID. User explicitly chose seller cancellation only before confirmation. State/ownership checks execute inside serializable transactions; existing inventory, voucher and shipment release logic is reused. No schema changes.
- Buyer endpoint POST `/api/orders/{id}/cancel` now requires `{ "reason": "Không còn nhu cầu mua" }`. Accepted buyer reasons are in `OrderCancellationReasons.BuyerChoices`; missing/custom buyer reasons return 400. Old clients sending no reason must be updated.
- Seller PUT `/api/seller/stores/{storeId}/orders/{id}/status` accepts `{ "status": "CANCELLED", "reason": "..." }`. Preset or custom reason is required, trimmed, 1–500 characters. Existing confirmation contract remains supported. SellerService receives IOrderService through DI; manually constructed cancellation callers must supply it.
- Authenticated actor is saved in history ChangedByAccountId. History Note names buyer/store and includes the reason. Buyer notifications distinguish `Bạn đã hủy đơn thành công với lý do: ...` from `Cửa hàng đã hủy đơn của bạn với lý do: ...`; seller receives corresponding actor-appropriate wording. Repeat cancellation preserves original history/reason and does not notify twice.
- Both confirmation paths send full customer wording. FE also expands legacy `Đã xác nhận` order messages for display. Historical cancellation messages are not rewritten because their actor/reason is unknown.
- FE: order list and detail show a reason form before submission, hide it if the order is no longer cancellable, and refresh orders/detail/membership/vouchers/notifications on success. Seller detail offers cancellation only for unpaid pending orders, with presets and a custom text field. Form controls are siblings; no nested buttons/modal.
- Verification: 467 frontend tests and 211 seller tests pass; both typecheck/lint pass. Backend builds; 19 focused cancellation/seller-read/voucher/checkout/affiliate tests pass, including actor/recipient messages, reason validation, mixed-store denial, resource release, idempotency and state guards. Real browser fixtures checked buyer selection/keyboard submission and seller custom submission; mobile layout has no overflow, console clean. Fixtures removed.

Three unrelated existing schema tests fail: PostgresFlowTests expects 68 model entities (actual 72); ReviewImagesJsonTests and StoreOwnedProductsFlowTests insert legacy Products without required ShortDescription. Relevant assertions/legacy migration setup were not changed. Reports: ignored `.local/cancellation-test-results/full.trx`.
