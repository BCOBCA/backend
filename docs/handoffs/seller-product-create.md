# Seller product creation

> Updated requirements: see [flexible products](seller-product-variants.md). This update supersedes the original 8-image, typed-field and single-variant scope below.

- Authenticated `GET /api/seller/stores/{storeId}/product-options` returns active brands and categories with parent IDs, excluding deleted brands and categories beneath inactive ancestors. Active account and active owned seller store are required.
- `POST /api/seller/stores/{storeId}/products` accepts `SellerCreateProductInput`, returns 201 with `SellerProductDto`. Body limit 256 KiB. Route supplies ownership; privileged admin/ownership fields are absent from the input and ignored if forged.
- Required: request UUID, brand/category, name <=250, positive integer VND price, nonnegative int stock, 1–8 distinct HTTPS images, shipping weight 1–50000 g and each dimension 1–200 cm. Optional descriptions, sale price <= price, visibility and typed product/variant attributes. Existing specification rules enforce category requirements and types.
- `SellerService` reuses injected `IAdminCatalogService.SaveProductAsync` for the transactional product/default-variant/image/inventory-ledger/audit write. Existing admin contracts are unchanged. The optional constructor dependency preserves standalone read-only test/service construction; runtime DI already registers the writer.
- Generate `SP-{requestId:N}` SKU, a default active variant with deterministic SKU, and a normalized name + request UUID slug. Existing scoped SKU returns the saved DTO on retry. Unique variant SKU prevents concurrent duplicate commits. No schema migration, marketplace verification gate or role elevation added.
- One default sale option is created; advanced multi-variant editing and seller update/status endpoints are outside scope. Hiding sets product status 0, preserving its inventory.
- Verification: SellerProductCreateTests cover ownership, active catalog/account, inactive category ancestors, prices/images/shipping, required typed attributes, inventory/audit and retry. SellerProductCreateHttpTests exercises real localhost JSON binding, authentication, spoofed ownership/featured fields and retry. Related profile/branch/verification HTTP tests pass (7 focused tests total). All DB work used localhost:55433 scratch databases; no production writes or deployment.
