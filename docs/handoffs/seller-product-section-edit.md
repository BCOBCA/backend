# Seller product section updates

- PUT `/api/seller/stores/{storeId}/products/{id}/{section}` supports basic/images/description/variants/stock/info/shipping/status with explicit `SellerProductSectionInput` and expected UpdatedAt. GET detail advertises supportsSectionUpdates and CategoryId. Unknown/privileged fields do not enter mutation mappings.
- Serializable transaction authorizes active owner/store/product, compares exact expected version, validates selected section, advances UpdatedAt at PostgreSQL microsecond precision, appends audit and returns refreshed detail. Stock deltas alone append ADJUSTMENT movements, never touching ReservedQuantity. Exact existing variant ID set required; no variant removal/addition or SKU/owner/brand transfer.
- Boundaries: integer VND/sale<=price, normalized distinct names, stock>=current reservations and sum<=int32, 1–5 distinct HTTPS credential-free photos, 20k text, active category changes and shipping 1–50000g/1–200cm. Unedited sections/legacy specs retained; explicit info save writes free_text. No schema migration or production writes.
- Tests: full section round-trip, invalid bounds/URLs/categories/IDs, unrelated field isolation, stale token 409, foreign-owner denial, reservations and ledger/audit, simultaneous same-version updates allowing exactly one success, and actual HTTP PUT success/stale/foreign rejection. Run with localhost:55433 scratch PostgreSQL only.
