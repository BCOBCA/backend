# Dealer product storefront

- `StoreProducts(StoreId,ProductId)` explicitly links dealers to products; composite PK and FKs preserve existing Brand/product/cart ownership. Migration `20261107075451_AddStoreProducts` adds only this table and its reverse lookup index.
- `IDealerCatalogService`: GET `/api/dealers/{id}/products` with page/pageSize/categoryId/minPrice/maxPrice/sort (popular/newest/price-asc/price-desc); GET `/api/dealers/{id}/product-categories` returns active leaf categories/counts from store assignments and actual linked products.
- Product visibility requires active public dealer, active product/brand, and active category ancestry. Default variant follows existing catalog stock/price/ID order; range filtering and sort use that displayed price. Count/pagination happen in SQL. Ratings use approved ProductReviews; sales use completed order items, globally per product because existing cart/orders are brand-scoped. No sample ratings/sales are inserted.
- CategoryTree provides cycle-safe active ancestry/descendants; directory and global product category filters include children. The main category grid remains at the root level.
- Prepared demo catalog: `docs/data/dealer-products-demo-2026-11-07.json`, 11 child categories and 21 products with sample prices/stock. Images come from DummyJSON and were decoded/hosted with preserved alpha on configured Cloudinary under `bcobca/demo-products-v2/`. Unbranded kitchen demo items use a clearly named `Gia dụng mẫu` brand instead of attributing them to a real manufacturer.
- At user request, migration and seed were applied to configured Neon neondb: 21 products, 51 child StoreCategories assignments and 93 StoreProducts links across all ten imported dealers. Seed uses stable IDs, adds missing rows only, refuses conflicting existing sample rows, and stores a before-state backup at `.local/storefront-assets/before-20261107-081045-6114.json`. Execution/preparation helpers stay under ignored `.local/storefront-assets/`.
