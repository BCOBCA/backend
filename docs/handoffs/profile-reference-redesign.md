# Personal profile reference redesign

- Expanded `ProfileDto` with coverUrl, gender, nullable birthday, referral link/public nickname, timestamps, account status and verification flags. Existing optional constructor contracts remain compatible. No schema migration: values already exist in Users/Accounts.
- `UpdateProfileRequest` appends optional coverUrl/gender/dateOfBirth. Omission preserves these fields; empty birthday clears the legacy sentinel. Validate HTTPS images, gender0..2 and actual nonfuture dates since1900. Account role/status/referral/date-created/verification cannot be changed by submitting profile fields. Changing a phone continues to clear PhoneVerified.
- Referrer lookup exposes only an active user's public nickname, never another user's private full name or contact details. Unknown/absent relationships remain distinct in the frontend.
- Added authenticated, image-rate-limited `POST /api/auth/profile-images` multipart upload for active accounts. Reuses existing Cloudinary image validation (JPEG/PNG/WebP, max5MB), random IDs and response validation. Normal customers are supported; disabled/unauthenticated accounts are denied. Uploading returns an image URL; only the owner's existing PUT /auth/me persists it.
- Frontend profile is rebuilt around identity cover/avatar/menu, account table and explicit edit/save/cancel. Uses actual data, no invented dates/status/portrait. Decorative SVG is only a fallback cover. Mobile uses horizontal menu and stacked facts. Referral copy and existing password/session/notification/dealer profile links remain functional.
- Gallery picker uses SDK-compatible expo-image-picker, no camera/microphone permissions. Native binaries need rebuilding for the new module/plugin. Web selects a File; native sends a file URI as multipart. Canceled, invalid-type and oversize selections do not upload. No real Cloudinary uploads were performed during testing.
- Phone verification panel displays real status plus edit/support actions: there is no SMS/OTP provider, and the UI never simulates verification. Existing email verification is retained.
- Validation: backend full suite140 passed plus new isolated active-customer upload authorization test; frontend full suite160 passed, TypeScript/lint/web export passed. PostgreSQL profile tests cover metadata preservation/clearing/validation and referrer privacy. Upload provider is mocked. Browser fixtures at1440/390 px verify layout/no overflow, cancel without saving, save nickname/birthday, referral copy and truthful verification status. No production profiles/messages/uploads changed.
- An existing API process locks the normal debug DLLs; testing uses ignored `.local/profile-test-artifacts` instead of stopping it. Browser fixture/build is under ignored `.local/profile-ui/`.
- Backend/frontend need deployment together to display/edit all new metadata and enable upload. No push or deployment performed for this redesign.
